Critical requirement: all bounds stored in property.json must be WGS84 / EPSG:4326 longitude/latitude.

A previous admin version incorrectly wrote projected coordinates such as:

450411.63
6567830.065

from an EPSG:32756 source directly into JSON. The admin processor was subsequently changed to perform CRS-aware conversion to WGS84.

6. Admin processing pipeline

Three stages:

1. Analyse
2. Process locally
3. Publish / Retry Publish
Analyse

Finds:

result.tif
NDVI.tif
GNDVI.tif

as applicable.

RGB-only surveys are supported.

Multispectral datasets may contain:

RGB
NDVI
GNDVI

with architecture intended to support additional indices later.

It reads:

dimensions
CRS
raster bounds
index ranges

and converts bounds to EPSG:4326.

Process locally

For RGB:

gdal2tiles.py \
  -z 14-20 \
  -w none \
  result.tif \
  <work>/tiles/rgb

Current maximum was deliberately throttled back to zoom 20 because zoom 22 generated roughly a gigabyte of PNGs even for a modest RGB survey.

For multispectral indices the proven processing pipeline is:

Extract RGB alpha footprint.
Align footprint to index raster.
Mask index raster outside RGB footprint.
Convert outside pixels to -9999.
Colour-relief index.
Generate PNG tiles.
Upload tiles.

Example mask:

gdal_calc.py \
  -A NDVI.tif \
  -B rgb_mask_aligned.tif \
  --calc="where(B>0,A,-9999)" \
  --NoDataValue=-9999 \
  --type=Float32 \
  --outfile=NDVI_masked.tif \
  --overwrite

Colour table:

-9999 0 0 0 0
-1.00 165 0 38 255
0.00 215 48 39 255
0.20 244 109 67 255
0.40 254 224 139 255
0.55 217 239 139 255
0.70 102 189 99 255
0.85 26 152 80 255
1.00 0 104 55 255

Then:

gdaldem color-relief \
  NDVI_masked.tif \
  index-colours.txt \
  NDVI_colour.tif \
  -alpha

followed by gdal2tiles.py.

This footprint masking fixed the original orange rectangular backgrounds and stair-step index artefacts.

Publish

Uploads with AWS CLI:

aws s3 sync \
  <local tiles> \
  s3://southern-skies-maps/<property>/<paddock>/<date>/<layer> \
  --endpoint-url https://28b52d96eac801a46d9f752dc25c6cb4.r2.cloudflarestorage.com

Updates property.json, generates/updates portal pages, commits and pushes Git.

The admin also has Publish / Retry Publish, allowing an already processed job to be published again without rerunning GDAL.

This was added after Git conflicts caused completed local processing/uploads to be stranded.

9. Shared map viewer

Current map viewer loads:

/maps/config.js
/maps/explorer/explorer.js
/maps/ui/ssa-ui.js
/maps/ui/ssa-ui.css

and obtains the selected survey from:

/portal/${client}/property.json

using URL parameters for:

client
paddock
survey/date

MapLibre initializes from the survey's:

center
bounds
layers

Survey imagery is dynamically loaded as a raster source.

Core behaviour is equivalent to:

const layerKeys = Object.keys(s.layers);

function show(k) {
    const layer = s.layers[k];

    if (map.getLayer("survey")) {
        map.removeLayer("survey");
    }

    if (map.getSource("survey")) {
        map.removeSource("survey");
    }

    map.addSource("survey", {
        type: "raster",
        tiles: [layer.tiles],
        tileSize: 256,
        scheme: layer.scheme || "tms",
        minzoom: layer.minzoom || 14,
        maxzoom: layer.maxzoom || 20,
        bounds: [
            s.bounds[0][0],
            s.bounds[0][1],
            s.bounds[1][0],
            s.bounds[1][1]
        ]
    });

    map.addLayer({
        id: "survey",
        type: "raster",
        source: "survey"
    });
}

The actual current files contain additional shared explorer/measurement logic; the complete exact byte-for-byte contents of the current repository files are not available in this handoff context, so they should be inspected from the repository before the next patch rather than reconstructed from this summary.

That is particularly important now because repeated replacement patches caused the current regression.

10. Basemaps

Two basemap choices:

Map
Satellite

Satellite is the desired/default primary view.

Satellite comes from the ArcGIS Basemap Styles API.

The API key is stored via:

/maps/config.js

and referenced through:

SSA_CONFIG?.ESRI_API_KEY

Do not expose or repeat the actual key.

The key is referrer restricted.

The working architecture loads the Esri imagery style once rather than repeatedly calling map.setStyle(). Basemap layers are toggled for Map/Satellite switching so survey layers remain intact.

11. Terra-style imagery/index selector

The desired viewer control is modelled on DJI Terra.

Instead of hiding imagery selection in the Layers dialog, a permanent bottom strip should show only layers available for that dataset:

MAP | SATELLITE | RGB | NDVI | GNDVI

or, for RGB-only:

MAP | SATELLITE | RGB

Potential future multispectral set:

MAP | SATELLITE | RGB | NDVI | GNDVI | LCI | NDRE | OSAVI

This is generated dynamically from:

Object.keys(s.layers)

rather than hard-coded per property.

The relevant existing viewer identifiers from the last known working selector implementation are:

id="terraStrip"
buildTerraStrip

Compare has:

id="compareStrips"
buildCompareStrips

and uses:

__satellite__

as a selectable comparison source.

12. Index information

When an index such as NDVI/GNDVI is selected, the design calls for:

appropriate colour scale
short explanation of what the index measures
short description of its agricultural use

This should appear automatically based on the selected index.

RGB and Satellite do not require vegetation-index legends.

13. Compare / swipe system

Swipe comparison was successfully implemented and is considered an important client feature.

It allows two imagery states to be compared with a draggable vertical divider.

Desired logic:

survey vs survey
RGB vs index
index vs index
survey vs satellite
if only one survey dataset exists, automatically make satellite available as the other side

The compare application is shared:

/maps/compare/index.html

rather than generated separately for every property.

15. Polygon rendering bug that was solved

For several versions:

calculations worked
hectares/perimeter were correct
polygon fill could appear
polygon/path outlines were invisible

This initially looked like a MapLibre layer ordering issue.

Several attempts to force MapLibre measurement layers above the survey raster failed.

The successful solution was to stop depending on MapLibre's layer stack for the interactive measurement geometry.

The current measurement geometry is rendered using a dedicated SVG overlay above the MapLibre canvas.

Known identifiers include:

ssa-measure-overlay
renderOverlay

This solved the problem.

Confirmed working result:

bright cyan polygon outline visible above RGB orthomosaic
dark contrast stroke beneath it
polygon remains visible with shading off
area calculation works

Example confirmed result:

5.707 ha
57071 m²
perimeter 1.39 km

This is the measurement implementation that must not be reverted.
